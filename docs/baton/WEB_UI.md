# Baton — веб‑интерфейс

`baton-server` отдаёт веб‑интерфейс по адресу `https://<сервер>/ui/` (корень `/` перенаправляет туда). Интерфейс показывает то же, что API, с теми же правами: список проектов, знания и их актуальность, сессии и их состояние, конфликты синхронизации и журнал аудита. Люди подтверждают знания или помечают их устаревшими прямо со страницы записи.

Стек: React 19 и Mantine 9 (UI‑кит: таблицы, вкладки, формы, светлая и тёмная темы), иконки Tabler, сборка Vite. Исходники — `src/server/central/web`, сборка — `npm run build:ui` (входит в `npm run build`) в `dist/server/central/ui`.

## 1. Вход

Вход по личному токену (`baton_pat_…`), тому же, что для CLI. Администратор выдаёт его командой `baton-server issue-token <email> --days 90` (OPERATIONS.md §4). По умолчанию токен хранится в `sessionStorage` вкладки и пропадает при её закрытии; флажок «Запомнить на этом устройстве» кладёт его в `localStorage`. «Выйти» удаляет токен из обоих хранилищ. Ответ `401` (токен отозван или истёк) возвращает на страницу входа.

## 2. Страницы

| Страница | Адрес | Что показывает | Кому |
|---|---|---|---|
| Проекты | `#/` | Все доступные проекты: роль, число знаний, на проверку (`needs_review`), не подтверждено, активные сессии, ждущие продолжения, открытые конфликты, время последнего изменения знаний и последнего анализа git | все роли |
| Обзор проекта | `#/p/<id>` | Плитки с итогами; знания по категориям, доверию и статусу; сессии по статусам; курсоры анализа git по веткам; обзор проекта (контекст L1, тот же, что получают агенты) | viewer+ |
| Знания | `#/p/<id>/knowledge` | Фильтры по категории, доверию, статусу, компоненту, файлу; поиск (hybrid, как у агентов); постраничный список | viewer+ |
| Запись | `#/m/<id>` | Содержание, факты, связанные файлы, автор (человек и агент), источник, ключ темы, история версий с причинами; кнопки «Подтвердить» и «Пометить устаревшим» (с причиной) | чтение — viewer+, подтверждение — developer+ |
| Сессии | `#/p/<id>/sessions` | Все сессии проекта с фильтром «активные / ждут / завершённые»: задача, статус, пользователь, агент и модель, устройство, номер checkpoint, lease | viewer+ (без перехода к деталям) |
| Сессия | `#/s/<id>` | Следующее действие, сделано и осталось, решения, проблемы, изменённые файлы и неотправленные коммиты, handoff brief, цепочка продолжений, checkpoints (в том числе `orphan`), снимки рабочей копии | developer+ |
| Конфликты | `#/p/<id>/conflicts` | Открытые конфликты синхронизации: какая версия осталась, какая отброшена, кем | viewer+ |
| Журнал аудита | `#/p/<id>/audit` | Кто, когда, с какого устройства и что сделал в проекте | maintainer, admin |
| Поиск | `#/search?q=…` | Поиск по всем доступным проектам | все роли |

Интерфейс на русском и английском (меню пользователя; по умолчанию — язык браузера), светлая и тёмная темы (по умолчанию — как в системе). Таблицы на узком экране прокручиваются внутри себя, страница по ширине не прокручивается; поиск на телефоне — в меню‑бургере.

**Актуальность знаний** видна по трём признакам: доверие (`proposed` / `observed` / `inferred` — агент, `confirmed` — человек, `deprecated` — устарело), статус `needs_review` (коммит изменил связанные файлы, CONTEXT_ENGINE.md, «Устаревание») и время последнего анализа git. Подтверждённое знание синхронизация не меняет; устаревшее не попадает в контекст агентов.

## 3. API, на котором он построен

Интерфейс не обращается к базе напрямую: только к `/v1` с заголовком `Authorization: Bearer`. Для него добавлены:

| Метод | Путь | Роль | Описание |
|---|---|---|---|
| GET | `/v1/projects/:id/stats` | viewer+ | Знания по категориям, доверию и статусу; `needsReview`, `unconfirmed`, `lastUpdatedAt`; сессии по статусам; открытые конфликты; курсоры git. Подсчёт идёт под RLS вызывающего |
| GET | `/v1/projects/:id/audit?limit=&before=` | maintainer+ | Журнал аудита проекта, новые сверху; `before` — id последней показанной записи |
| GET | `/v1/projects/:id/memories?offset=` | viewer+ | Постраничный список (добавлен `offset`) |

Записи памяти и их версии теперь содержат email автора (`authorEmail`, `changedByEmail`).

## 4. Безопасность

- **Нет cookies**, поэтому нет CSRF: каждый запрос несёт токен в заголовке, который чужая страница поставить не может.
- **CSP**: `default-src 'none'; script-src 'self'; style-src 'self' 'nonce-…'; connect-src 'self'; frame-ancestors 'none'` — без inline‑скриптов, без внешних ресурсов, без встраивания в чужие страницы. Mantine пишет CSS‑переменные темы в элемент `<style>`; он получает nonce, который сервер генерирует заново для каждой загрузки страницы и подставляет в `index.html` и заголовок. `'unsafe-inline'` не используется. Стили элементов React задаёт через CSSOM, который CSP не ограничивает.
- **Нет вывода HTML**: React экранирует все значения; в исходниках интерфейса нет `dangerouslySetInnerHTML`, `innerHTML` и подобного (это проверяет тест).
- **Файлы интерфейса** читаются в память при старте сервера; путь запроса только ищется в этой таблице и не доходит до файловой системы. Файлы `assets/` с хешем в имени кешируются надолго (`immutable`), `index.html` — `no-cache`.
- **Права** проверяет сервер: интерфейс лишь скрывает недоступные действия. Viewer не видит деталей сессий и кнопок подтверждения; прямой запрос всё равно получит `403`.
- **Токен в браузере**: XSS украл бы его, поэтому CSP и `textContent`; «Запомнить» — только на личном устройстве. Выдавайте токены со сроком (`--days`).

## 5. Эксплуатация

- Интерфейс входит в образ и включён по умолчанию. Отключить: `BATON_UI=0` — тогда `/` и `/ui/` отвечают 404, API работает как прежде.
- Caddy проксирует все пути, отдельной настройки не нужно.
- Файлы лежат в `dist/server/central/ui` (собираются `npm run build`); React, Mantine и Vite — dev‑зависимости, серверу во время работы не нужны. Без собранного интерфейса сервер работает, а `/ui/` отвечает «не установлен».
- Разработка: `npm run build:ui` после изменений в `src/server/central/web`; `npm run lint` проверяет типы и сервера, и интерфейса.

## 6. Проверка

- `tests/central/web-ui.test.ts`: раздача собранного приложения и CSP с новым nonce на каждую загрузку, отсутствие вывода HTML в исходниках, отсутствие путей к файлам, отключение, подсчёты под RBAC и RLS (outsider — 404, без токена — 401), подтверждение и устаревание с изменением подсчётов, email авторов в версиях, постраничный список, журнал аудита только для maintainer+ и его страницы, наличие файлов в сборке.
- Ручная проверка в браузере на демо‑сервере (два пользователя, два проекта, знания, handoff, снимок): все страницы, фильтры, подтверждение и пометка устаревшим (с обязательной причиной), вход и выход, роль developer без журнала аудита, русский и английский, светлая и тёмная темы, ширина телефона без горизонтальной прокрутки; в консоли нет ошибок и нарушений CSP, все `<style>` Mantine с nonce.
